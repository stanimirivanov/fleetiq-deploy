# FleetIQ installation and qualification language

Installation vocabulary extends the [shared product glossary](https://github.com/stanimirivanov/fleetiq-platform/blob/main/GLOSSARY.md). Qualification claims always name their evidence boundary.

## Language

**Installation**: A configured composition of selected FleetIQ artifacts and operational resources.

**Release candidate**: An inert reviewed selection of artifacts and release inputs proposed for an environment.

**Release request**: An immutable request identifying a reviewed candidate for release execution.

**Activation**: The authorized selection and application of release inputs to an installation.

**Release receipt**: Retained evidence of an execution outcome, including failed or recovery-required outcomes; it does not alone establish installation health.

**Protocol conformance**: Evidence that tested protocol behavior satisfies its specified boundary.

**Component compatibility**: Evidence that selected producer and consumer versions work together at a stated interface.

**Installed-product qualification**: Evidence from the assembled application exercising a stated end-to-end behavior in a specified environment.

**Hardware qualification**: Evidence scoped to tested physical devices, firmware and conditions; simulator behavior alone does not establish it.

**Recovery-required state**: A retained release outcome requiring reviewed recovery before further admission.

**Qualification constraint**: A limit of the tested setup or supported test profile; it is not automatically a product capacity promise.
